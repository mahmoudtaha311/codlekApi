# codlekApi

Web API بكلين أركتكتشر لنظام كودلك (ورشة صيانة لابات).

> الملف ده للي بيمسك المشروع من الأول.

## 🔴 الريبو ده نص النظام، مش النظام كله

فيه **مشروع تاني شغّال على الإنتاج دلوقتي** (`CodlekWeb` — Minimal API
+ Razor Pages) ومعاه برنامج ويندوز على الراكات. الريبو ده **إعادة بناء
منظّمة للسيرفر**، بيتعمل جنب القديم، والقديم **مايتلمسش ويفضل شغّال**
لحد ما الجديد يبقى stable.

يعني فيه تلات حاجات بتربط الريبو ده بحاجات برّه، ومينفعش تتغيّر من
هنا لوحدها:

| | |
|---|---|
| **نفس قاعدة البيانات** | الـ٣١ جدول مملوكين للمشروع القديم |
| **أرقام الـenums** | برنامج الراكة بيقراها كأرقام على السلك |
| **أسماء حقول الـJSON** | الراكة والداش بورد بيقروها بالأسماء دي |

### فين المشروع القديم

الريبو ده مستنسخ جوّه مشروع القديم على جهاز التطوير:

```
spics/
  spics/                  برنامج الراكة (WPF)
  web/
    CodlekWeb/            السيرفر القديم — شغّال على الإنتاج
    CodlekWeb.Tests/      ١ُ٠٥٧ فحص — وهم المعيار
    codlek-dashboard/     الواجهة (React)
    new-api/              ← **الريبو ده**
```

🔴 **و`new-api/` متحطوط في `.gitignore` بتاع `web`.** لأنه ريبو
جوّه ريبو: أول `git add .` من `web` كان هيسجله كـgitlink — رقم
commit وبس من غير أي ملف. فالشغل هنا بيتحفظ من جوّه الفولدر
ده نفسه.

⚠️ والسلوك والمقارنات هنا منقولين من القديم **بالحرف** — راجع
«المقارنات لازم تبقى زي القديم» تحت، وفيها حالة موثّقة.

## الأربع مشاريع + الفحوص

```
CodlekApi.sln          الحل — افتحه تلاقي الخمسة

Codlek.Core            كيانات + enums + قواعد نقية، من غير أي اعتماد
Codlek.Application     → Core        أوامر/استعلامات بـMediatR، Result<T>، عقود
  Features/                          فيتشر لكل مجلد، وجوّاه مجلد لكل حالة
  Contracts/                         اللي بيخرج للواجهة
  Interfaces/                        واجهات المستودعات والخدمات
  Abstractions/                      Result · Error · أكواد السجل
  Behaviors/                         التحقق قبل كل أمر
Codlek.Infrastructure  → Application DbContext، التوكنات، Identity
Codlek.Api             → الاتنين     كنترولرز، Program.cs قصير
Codlek.Tests           → الأربعة     ٤٤٧ فحص
```

🔴 **نوع واحد في كل ملف.** مش قاعدة شكلية: `git log` على ملف واحد
يوريك تاريخ الحاجة دي بالظبط، وأي تعديل بيبان في المراجعة بدل ما
يضيع في ملف ٥٠٠ سطر.

الاستثناء الوحيد: `Result` و`Result<T>` — زوج عام، مكانه ملف واحد.

## الشكل اللي بيتكرر — قطاع `departments` هو القالب

🔴 **القطاع ده اتعمل الأول عن قصد: صغير وكامل.** قطاع كبير وناقص
(زي الأجهزة بـ١٦ فلتر) كان هيثبت الشكل غلط — الداش بورد بتاخد عقد
ناقص وبتعرض خانات فاضية من غير أي خطأ.

```
Codlek.Application/Departments/
  DepartmentErrors.cs                 أسباب الفشل، كل واحد بكوده
  GetDepartments/
    GetDepartmentsQuery.cs
    GetDepartmentsQueryHandler.cs
  CreateDepartment/
    CreateDepartmentCommand.cs
    CreateDepartmentCommandValidator.cs
    CreateDepartmentCommandHandler.cs
  UpdateDepartment/ (نفس التلاتة)

Codlek.Application/Contracts/Departments/   العقود اللي بتخرج للواجهة
Codlek.Application/Interfaces/Repositories/ الواجهة
Codlek.Infrastructure/Repositories/         التنفيذ بـEF
Codlek.Api/Controllers/                     الكنترولر
```

### القواعد اللي بتتكرر في كل قطاع

| | |
|---|---|
| الشركة من `ICurrentUser` | **عمرها ما تيجي من الطلب** |
| الأمر مافيهوش `TenantId` | فمفيش طريقة حد يبعت شركة تانية |
| صف شركة تانية = `404` | مش `403` — `403` بيأكّد إن المعرّف حقيقي |
| السجل والتغيير في حفظة واحدة | `IAuditTrail.Record` بيضيف ومابيحفظش |
| الرفض مابيحفظش ومابيسجّلش | فيه فحص بيثبّت ده |
| الحقل الناقص في التعديل = «ماتغيّرش» | **مش «فضّيه»** |
| فحص التكرار بيستني الصف نفسه | وإلا أي حفظ من غير تغيير اسم بيترفض |
| مستودع لكل قطاع، دواله بتاخد `tenantId` إجباري | مش `IGenericRepository<T>` |

⚠️ **والمقارنات لازم تبقى زي القديم بالحرف** — المشروعين هيشتغلوا على
نفس القاعدة فترة التحويل. أي اختلاف معناه نفس الطلب ينجح من شاشة
ويترفض من التانية. فيه حالة موثّقة في `IDepartmentRepository`.

## إزاي تشغّله محلياً

```bash
dotnet user-secrets --project Codlek.Api set "Jwt:Key" "<٣٢ حرف على الأقل>"
dotnet user-secrets --project Codlek.Api set "ConnectionStrings:SqlServer" \
  "Server=localhost;Database=codlek_dev;Trusted_Connection=True;TrustServerCertificate=True"

dotnet build Codlek.Api/Codlek.Api.csproj -m:1
ASPNETCORE_URLS=http://127.0.0.1:5319 dotnet run --project Codlek.Api --no-build
```

⚠️ **`-m:1` على `dotnet build` بس.** على `dotnet run` بيتبعت للبرنامج
كمُعامل أول (`args[0]`) — ودي ضيّعت ساعة هنا: harness كان بياخد
الباسورد من `args[0]` فعمل بصمة لـ`-m:1`، والنتيجة «الدخول مش شغّال»
وهو شغّال.

## 🔴 أربع حاجات لازم تعرفها قبل أي تعديل

### ١ · أرقام الـenums عقد مجمّد

الراكة بتقراها **كأرقام على السلك**. تغيير رقم واحد = الراكة تفهم
«قيد الصيانة» على إنها «تمت الصيانة»، من غير خطأ ومن غير ما حد ياخد
باله. التفاصيل في `Codlek.Core/Enums/README.md`.

### ٢ · الـschema مملوكة للمشروع القديم

الزيادة مسموحة، وتعديل أي حاجة في الـ٣١ جدول ممنوع. وده **بيتقاس**
مش بيتوعد بيه — `Codlek.Infrastructure/Data/SCHEMA-GATE.md` فيه إزاي.

والهجرات بتتعمل على `codlek_dev` (قاعدة محلية)، مش على الإنتاج.

### ٣ · اسم نص الاتصال `SqlServer` مش `DefaultConnection`

الاستضافة فيها `ConnectionStrings__SqlServer` في `web.config`. ولو
الجديد دوّر على الاسم الافتراضي، **السيرفر المنشور يقوم على قاعدة
فاضية ويقول إنه شغّال**. فيه فحص بيثبّت الاسم ده.

### ٤ · الباسوردات القديمة والجديدة مع بعض

`LegacyPasswordHasher` بيفهم الاتنين، والترقية بتحصل لوحدها أول ما
المستخدم يدخل. من غيره **كل مستخدم في النظام مايدخلش بعد التحويل**.

🔴 والباج اللي اتمسك هنا يستحق قراءة: العمودين (`PasswordHash` و
`LegacySalt`) بيوصفوا حاجة واحدة، و`UserManager` كان بيحدّث واحد بس
— فالمستخدم كان بيدخل **مرة واحدة** بعد الترقية وبعد كده خلاص.
والتفاصيل في تعليقات الكلاس نفسه.

## الحاجات اللي ماخدناهاش من المشروع المرجعي

لقيناها في `FixFlow` وهي أعطال حقيقية — متتكررش:

| | إزاي اتجنّبناها |
|---|---|
| ١٣ متحقّق مكتوبين و**مفيش حاجة بتنديهم** | `ValidationBehavior` مسجَّل في نفس نداء `AddMediatR` |
| `app.UseAuthentication()` **ناقصة** | موجودة، وقبل `UseAuthorization` |
| نمطين متنافسين (MediatR + خدمات بالإيد) | MediatR وبس |
| **مفيش ولا فحص** في الحل كله | ٨١ فحص |
| أسرار مكتوبة في `appsettings.json` | user-secrets محلياً، متغيّرات بيئة على الاستضافة |

## الفحوص — إزاي بتتكتب هنا

```bash
dotnet build Codlek.Tests/Codlek.Tests.csproj -m:1   # ⚠️ لازم قبل الفحص
dotnet test  Codlek.Tests/Codlek.Tests.csproj -m:1 --no-build
```

🔴 **اطبع نتيجة البناء دايماً.** `--no-build` على بناء فاشل بيشغّل
النسخة القديمة و**بيقول أخضر**. حصل هنا مرتين.

وكل قاعدة جديدة بتتكسر بالعمد بعد ما تتكتب، عشان نتأكّد إن الفحص
بيمسكها. ٢١ طفرة لحد دلوقتي، كلها اتمسكت.

**والقواعد النقية منفصلة عن الكود اللي بيلمس القاعدة** —
`RefreshRules.Evaluate` مثلاً فيها ٦ حالات رفض، وكل واحدة ليها فحص
بيخلص في مللي ثانية. لو كانت متشتّتة جوّه كود بيستعلم، كان هيتجرّب
منها واحد أو اتنين وبس.

⚠️ وفيه فحوص بتلمس قاعدة حقيقية (`LoginSessionTests`) — قاعدة
مخصوصة بتتعمل وتتمسح مع كل تشغيل. دي اللي بتثبت إن الكود **بيتنادى
فعلاً**، وهي الحاجة اللي الفحوص النقية مابتثبتهاش: حصل في المشروع ده
إن قاعدة اتكتبت واتجرّبت ومحدش بينديها.
