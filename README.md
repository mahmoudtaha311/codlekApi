# codlekApi

Web API بكلين أركتكتشر لنظام كودلك (ورشة صيانة لابات).

> الملف ده للي بيمسك المشروع من الأول. آخر تحديث: ٥ أكتوبر ٢٠٢٦.

## الحالة النهارده — باختصار

| | |
|---|---|
| السيرفر الجديد | ✅ **خلص**: ٨٥ نقطة للوحة + ١١ نقطة للراكة على مساراتها القديمة بالحرف |
| فحوص المشروع | ✅ **١٩٠٢ فحص** بيعدّوا |
| فحوص القديم على الجديد | ✅ **٨٤٤ من ١٠٥٧** — والباقي كله متصنّف بالسبب (`Codlek.ParityTests/README.md`) |
| بيئة تجربة على الاستضافة | ✅ **شغّالة على نسخة من بيانات الإنتاج** — شوف «بيئة التجربة» تحت |
| التحويل الحقيقي (الإنتاج) | ⏳ **مستني قرار المالك** — الخطوات في `CUTOVER.md` |

## 🔴 الريبو ده نص النظام، مش النظام كله

فيه **مشروع تاني شغّال على الإنتاج دلوقتي** (`CodlekWeb` — Minimal API
+ Razor Pages) ومعاه برنامج ويندوز على الراكات. الريبو ده **إعادة بناء
منظّمة للسيرفر**، بيتعمل جنب القديم، والقديم **مايتلمسش ويفضل شغّال**
لحد ما الجديد يتحوّل عليه.

يعني فيه تلات حاجات بتربط الريبو ده بحاجات برّه، ومينفعش تتغيّر من
هنا لوحدها:

| | |
|---|---|
| **نفس قاعدة البيانات** | الجداول القديمة مملوكة للمشروع القديم — الجديد بيزوّد بس |
| **أرقام الـenums** | برنامج الراكة بيقراها كأرقام على السلك |
| **أسماء حقول الـJSON ومسارات الراكة** | الراكة والداش بورد بيقروها بالأسماء دي، ومسارات الراكة مكتوبة جوّه البرنامج المنزّل |

### فين الباقي

الريبو ده مستنسخ جوّه مشروع القديم على جهاز التطوير:

```
spics/
  spics/                  برنامج الراكة (WPF)
  web/
    CodlekWeb/            السيرفر القديم — شغّال على الإنتاج
    CodlekWeb.Tests/      ١٬٠٥٧ فحص — وهم المعيار
    codlek-dashboard/     الواجهة (React) — بقت بتكلّم السيرفر ده
    new-api/              ← **الريبو ده**
```

🔴 **و`new-api/` متحطوط في `.gitignore` بتاع `web`.** لأنه ريبو
جوّه ريبو: أول `git add .` من `web` كان هيسجله كـgitlink — رقم
commit وبس من غير أي ملف. فالشغل هنا بيتحفظ من جوّه الفولدر ده نفسه.

⚠️ **والواجهة (`codlek-dashboard`) مش في الريبو ده** — هي في ريبو `web`
اللي مالوش نسخة على GitHub. تعديلاتها محفوظة هناك ونسخ احتياطي في
`web/backups/`.

## اللي اتعمل — بالمراحل

| # | المرحلة | |
|---|---|---|
| ١ | الهيكل + `Core`: الكيانات والـenums بأرقامها المجمّدة | ✅ |
| ٢ | `Infrastructure`: نفس الـschema بالظبط + Identity | ✅ مقاسة عمود عمود (`SCHEMA-GATE.md`) |
| ٢ب | الدخول: JWT + توكن تجديد في جدول + الباسوردات القديمة شغّالة | ✅ |
| ٣ | أول قطاع كامل (`departments`) — القالب اللي اتكرر | ✅ |
| ٤ | كل نقط اللوحة `/api/v1` | ✅ ٨٥ نقطة |
| ٥ | نقط الراكة — **على مساراتها القديمة بالحرف** (`/api/v2/*` و`/api/sync/reports`) | ✅ ١١ نقطة |
| ٥ب | فحوص القديم بتتشغّل على الجديد (`Codlek.ParityTests`) | ✅ ٨٤٤ / ١٠٥٧ |
| ٦أ | الواجهة اتنقلت للتوكن + سكريبت التحويل + نقل حسابات اللوحة | ✅ |
| ٦ب | **بيئة تجربة على الاستضافة بنسخة من الإنتاج** | ✅ ٥ أكتوبر |
| ٦ج | التحويل الحقيقي | ⏳ قرار المالك |

⚠️ **تصحيح مهم على الخطة الأولانية:** كانت بتقول نقط الراكة تتنقل لـ
`/api/v1/rack/*` والقديمة تبقى تحويلة. ده **اتعكس**: المسارات مكتوبة
جوّه البرنامج المنزّل على الراكات، والتحويلة خطر حقيقي — الراكة بتتبع
التحويل، ولو وقع على صفحة HTML بتقراها **نجاح** وبتمسح الشغل من
طابورها. فالمسارات القديمة هي الأصل، وفيه فحوص بتمنع أي مسار راكة يرجّع
HTML.

### عيوب في القديم اتلقطت واتصلّحت في الجديد

فحوص القديم لما اتشغّلت على الجديد لقت حاجات ناقصة — كلها اتنقلت:
قفل الباسورد المؤقت لحد ما يتغيّر، حدّ محاولات الدخول، سجل محاولات
الدخول و«آخر دخول»، شكل `auth/me`، حقل `message` في رسايل الخطأ،
الجرد والتسليم من غير الأجهزة المدموجة، ونقل حسابات اللوحة.

## بيئة التجربة (٥ أكتوبر ٢٠٢٦)

موقعين جداد على MonsterASP (واحد للسيرفر وواحد للوحة) وقاعدة جديدة
فيها **نسخة من قاعدة الإنتاج**. الإنتاج نفسه **مااتلمسش**. العناوين
والإعدادات **برّه الريبو** عن قصد — فيها أسرار.

| | النتيجة |
|---|---|
| الاسترجاع من نسخة الإنتاج + سكريبت التحويل | ✅ ٣٢ هجرة، والـ٣ حسابات اتنقلوا كلهم |
| حسابات حقيقية | ✅ شكل الباسوردات القديمة متطابق مع اللي السيرفر بيفهمه |
| كل الفحوصات والأجهزة (JSON، enums، تواريخ) | ✅ بتتقري من غير ولا غلطة |
| اللوحة على https بس + السيرفر بيقبلها من https بس | ✅ |
| رابط الـQR بيفتح على لوحة التجربة | ✅ |
| مسارات الراكة من غير مفتاح = `401` فاضي، ومفيش HTML على أي مسار | ✅ |
| راكة متمثّلة من أول التسجيل لحد ما الفحص يظهر في اللوحة | ✅ |
| الراكات الحقيقية | ⛔ **مش متوصّلة على التجربة** — قرار المالك وقت ما يقول |

### اللي اتلقط في التجربة واتصلّح

| | |
|---|---|
| 🔴 **إعادة تعيين باسورد أقصر من ٨ كانت بتقفل الحساب** | المدير يشيل القديم والجديد يترفض بعدها — الحساب يفضل من غير باسورد. دلوقتي الفحص الأول، ومتثبّت بفحص على قاعدة حقيقية |
| 🔴 Identity كانت لسه طالبة «حرف صغير» | باسورد أرقام بس أو عربي بس كان بيترفض. دلوقتي الطول بس — زي القديم |
| رسايل رفض الباسورد بالإنجليزي في الإنشاء وإعادة التعيين | بقت عربي في التلات أماكن من مكان واحد (`IdentityErrorText`) |
| سكريبت الرفع ممكن يتوجّه للإنتاج بالغلط | بقى بيرفع على مواقع التجربة بس، وبيتأكد من شهادة الاستضافة (`DeploySafetyTests`) |
| قالب `web.config` كان بينسخ الأسرار جوّه تعليقه | الخانات بقت جوّه القيم بس |
| ملف سكريبت ناقص في اللوحة كان بيرجّع الصفحة بدل ٤٠٤ | اتصلّح في `dashboard.web.config` |

## اللي لسه

| | |
|---|---|
| قرارات المالك قبل التحويل | في `CUTOVER.md`: اللوحة هتتقدّم منين، والتوكن في المتصفح، ومين يشغّل خطوات الإنتاج |
| صفحة الرفع اليدوي في القديم (`reports.json` / `accounts.json`) | مالهاش مقابل في الجديد — مستنية قرار: تتنقل ولا لأ |
| ربط الراكات | بعد ما المالك يخلّص تجربة اللوحة |
| ⚠️ ربط فحص جاي من غير `DeviceId` بجهاز مدموج | بيطلع «محتاج تحديد» بدل ما يتربط — القديم فيه نفس الثغرة، ومفيش فحص حالي متأثر، والراكات الحالية بتبعت `DeviceId` |

## الأربع مشاريع + الفحوص

```
CodlekApi.sln          الحل — افتحه تلاقي الكل

Codlek.Core            كيانات + enums + قواعد نقية، من غير أي اعتماد
Codlek.Application     → Core        أوامر/استعلامات بـMediatR، Result<T>، عقود
  Features/                          فيتشر لكل مجلد، وجوّاه مجلد لكل حالة
  Contracts/                         اللي بيخرج للواجهة والراكة
  Interfaces/                        واجهات المستودعات والخدمات
  Abstractions/                      Result · Error · أكواد السجل
  Behaviors/                         التحقق قبل كل أمر
Codlek.Infrastructure  → Application DbContext، التوكنات، Identity، الهجرات
Codlek.Api             → الاتنين     كنترولرز، Program.cs قصير
Codlek.Tests           → الأربعة     ١٩٠٢ فحص
Codlek.ParityTests                   فحوص القديم نفسها على الجديد
deploy/                              النشر على بيئة التجربة
```

🔴 **نوع واحد في كل ملف.** مش قاعدة شكلية: `git log` على ملف واحد
يوريك تاريخ الحاجة دي بالظبط، وأي تعديل بيبان في المراجعة بدل ما
يضيع في ملف ٥٠٠ سطر.

الاستثناء الوحيد: `Result` و`Result<T>` — زوج عام، مكانه ملف واحد.

## الشكل اللي بيتكرر — قطاع `departments` هو القالب

🔴 **القطاع ده اتعمل الأول عن قصد: صغير وكامل.** قطاع كبير وناقص
(زي الأجهزة بـ١٦ فلتر) كان هيثبت الشكل غلط — الداش بورد بتاخد عقد
ناقص وبتعرض خانات فاضية من غير أي خطأ.

```
Codlek.Application/Departments/
  DepartmentErrors.cs                 أسباب الفشل، كل واحد بكوده
  GetDepartments/
    GetDepartmentsQuery.cs
    GetDepartmentsQueryHandler.cs
  CreateDepartment/
    CreateDepartmentCommand.cs
    CreateDepartmentCommandValidator.cs
    CreateDepartmentCommandHandler.cs
  UpdateDepartment/ (نفس التلاتة)

Codlek.Application/Contracts/Departments/   العقود اللي بتخرج للواجهة
Codlek.Application/Interfaces/Repositories/ الواجهة
Codlek.Infrastructure/Repositories/         التنفيذ بـEF
Codlek.Api/Controllers/                     الكنترولر
```

### القواعد اللي بتتكرر في كل قطاع

| | |
|---|---|
| الشركة من `ICurrentUser` | **عمرها ما تيجي من الطلب** |
| الأمر مافيهوش `TenantId` | فمفيش طريقة حد يبعت شركة تانية |
| صف شركة تانية = `404` | مش `403` — `403` بيأكّد إن المعرّف حقيقي |
| السجل والتغيير في حفظة واحدة | `IAuditTrail.Record` بيضيف ومابيحفظش |
| الرفض مابيحفظش ومابيسجّلش | فيه فحص بيثبّت ده |
| الحقل الناقص في التعديل = «ماتغيّرش» | **مش «فضّيه»** |
| فحص التكرار بيستني الصف نفسه | وإلا أي حفظ من غير تغيير اسم بيترفض |
| مستودع لكل قطاع، دواله بتاخد `tenantId` إجباري | مش `IGenericRepository<T>` |

⚠️ **والمقارنات لازم تبقى زي القديم بالحرف** — المشروعين بيشتغلوا على
نفس القاعدة. أي اختلاف معناه نفس الطلب ينجح من شاشة ويترفض من التانية.
فيه حالة موثّقة في `IDepartmentRepository`.

## إزاي تشغّله محلياً

```bash
dotnet user-secrets --project Codlek.Api set "Jwt:Key" "<٣٢ حرف على الأقل>"
dotnet user-secrets --project Codlek.Api set "ConnectionStrings:SqlServer" \
  "Server=localhost;Database=codlek_dev;Trusted_Connection=True;TrustServerCertificate=True"

dotnet build Codlek.Api/Codlek.Api.csproj -m:1
ASPNETCORE_URLS=http://127.0.0.1:5319 dotnet run --project Codlek.Api --no-build
```

⚠️ **`-m:1` على `dotnet build` بس.** على `dotnet run` بيتبعت للبرنامج
كمُعامل أول (`args[0]`) — ودي ضيّعت ساعة هنا: harness كان بياخد
الباسورد من `args[0]` فعمل بصمة لـ`-m:1`، والنتيجة «الدخول مش شغّال»
وهو شغّال.

## النشر

- **بيئة التجربة:** `deploy/README.md` — والسكريبت بيرفع على مواقع التجربة بس.
- **الإنتاج:** `CUTOVER.md` — بالترتيب، ومعاه الرجوع لو حاجة وقعت.

🔴 **الأسرار عمرها ما تدخل الريبو ده** — هو عام على GitHub. مفتاح JWT
ونص الاتصال من user-secrets محلياً، ومن متغيّرات البيئة في `web.config`
على الاستضافة. وملفات النشر (`*.PublishSettings`) و`web.config` أي حاجة
متحطوطين في `.gitignore`.

## 🔴 أربع حاجات لازم تعرفها قبل أي تعديل

### ١ · أرقام الـenums عقد مجمّد

الراكة بتقراها **كأرقام على السلك**. تغيير رقم واحد = الراكة تفهم
«قيد الصيانة» على إنها «تمت الصيانة»، من غير خطأ ومن غير ما حد ياخد
باله. التفاصيل في `Codlek.Core/Enums/README.md`.

### ٢ · الـschema مملوكة للمشروع القديم

الزيادة مسموحة، وتعديل أي حاجة في الجداول القديمة ممنوع. وده **بيتقاس**
مش بيتوعد بيه — `Codlek.Infrastructure/Data/SCHEMA-GATE.md` فيه إزاي.

والهجرات بتتعمل على `codlek_dev` (قاعدة محلية)، مش على الإنتاج.

### ٣ · اسم نص الاتصال `SqlServer` مش `DefaultConnection`

الاستضافة فيها `ConnectionStrings__SqlServer` في `web.config`. ولو
الجديد دوّر على الاسم الافتراضي، **السيرفر المنشور يقوم على قاعدة
فاضية ويقول إنه شغّال**. فيه فحص بيثبّت الاسم ده.

### ٤ · الباسوردات القديمة والجديدة مع بعض

`LegacyPasswordHasher` بيفهم الاتنين، والترقية بتحصل لوحدها أول ما
المستخدم يدخل. من غيره **كل مستخدم في النظام مايدخلش بعد التحويل**.

🔴 والباج اللي اتمسك هنا يستحق قراءة: العمودين (`PasswordHash` و
`LegacySalt`) بيوصفوا حاجة واحدة، و`UserManager` كان بيحدّث واحد بس
— فالمستخدم كان بيدخل **مرة واحدة** بعد الترقية وبعد كده خلاص.
والتفاصيل في تعليقات الكلاس نفسه.

## الحاجات اللي ماخدناهاش من المشروع المرجعي

لقيناها في `FixFlow` وهي أعطال حقيقية — متتكررش:

| | إزاي اتجنّبناها |
|---|---|
| ١٣ متحقّق مكتوبين و**مفيش حاجة بتنديهم** | `ValidationBehavior` مسجَّل في نفس نداء `AddMediatR` |
| `app.UseAuthentication()` **ناقصة** | موجودة، وقبل `UseAuthorization` |
| نمطين متنافسين (MediatR + خدمات بالإيد) | MediatR وبس |
| **مفيش ولا فحص** في الحل كله | ١٩٠٢ فحص |
| أسرار مكتوبة في `appsettings.json` | user-secrets محلياً، متغيّرات بيئة على الاستضافة |

## الفحوص — إزاي بتتكتب هنا

```bash
dotnet build Codlek.Tests/Codlek.Tests.csproj -m:1   # ⚠️ لازم قبل الفحص
dotnet test  Codlek.Tests/Codlek.Tests.csproj -m:1 --no-build
```

🔴 **اطبع نتيجة البناء دايماً.** `--no-build` على بناء فاشل بيشغّل
النسخة القديمة و**بيقول أخضر**. حصل هنا أكتر من مرة.

وكل قاعدة مهمة بتتكسر بالعمد بعد ما تتكتب، عشان نتأكّد إن الفحص
بيمسكها — والطفرة اللي بتعدّي يا بتتقفل بفحص يا بتتوثّق إنها مكافئة.
الأرقام لكل جولة في `CUTOVER.md`.

**والقواعد النقية منفصلة عن الكود اللي بيلمس القاعدة** —
`RefreshRules.Evaluate` مثلاً فيها ٦ حالات رفض، وكل واحدة ليها فحص
بيخلص في مللي ثانية. لو كانت متشتّتة جوّه كود بيستعلم، كان هيتجرّب
منها واحد أو اتنين وبس.

⚠️ وفيه فحوص بتلمس قاعدة حقيقية (زي `LoginSessionTests`
و`UserPasswordResetTests`) — كل كلاس ليه قاعدة لوحده بتتعمل وتتمسح مع
كل تشغيل. دي اللي بتثبت إن الكود **بيتنادى فعلاً** وبنفس توصيل الإنتاج،
وهي الحاجة اللي الفحوص النقية مابتثبتهاش.
